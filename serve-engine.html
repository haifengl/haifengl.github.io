For agent loops

While Chatbots optimize for high throughput and long context streaming, agentic workflows care about something different: TTFT (Time to First Token) on frequent short prompts, rapid tool-call latency, and predictable memory overhead when running parallel loops. Our Serve Engine is built for that: a fast first token, a fast tool round trip, and a memory budget reserved when the model loads.

Tool results stay in the prefix

A tool result extends the same context. The cache is not rebuilt, and it does not grow one unbounded copy at a time.

Short turns are not held back

A request is admitted when its own prompt and token window fit. An interactive loop is not stalled until a large cohort fills.

Memory is reserved up front

KV and speculation checkpoints are sized at load. A long session does not grow the pool one request at a time.

The draft keeps its prefix

The draft head holds the prefix instead of recomputing it every round.

No second forward

On a partial accept, saved DeltaNet state is restored instead of another forward pass.

The gain holds in a full batch

Other serving engines lose the speculative advantage as the batch fills. SMILE holds it.

How it compares

vLLM

SMILE matches or slightly exceeds vLLM in raw decode throughput while outperforming it in speculative decoding scaling and hybrid architecture state management.

SGLang

SMILE achieves comparable token throughput and FlashInfer integration efficiency while offering a tighter execution pipeline for native speculative heads like MTP.

TensorRT-LLM

SMILE achieves TRT-LLM levels of low-level optimization (CUDA graphs for ragged verification batches, Marlin INT4 execution) without requiring heavy C++ compilation workflows or rigid engine builds.
