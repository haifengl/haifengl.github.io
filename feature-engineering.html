Feature Engineering

Feature quality often matters more than the choice of learning algorithm. SMILE’s smile.feature.* packages cover scaling, encoding, dimensionality reduction, imputation, selection, and tree-ensemble SHAP.

This page follows the same playground conventions as Classification and Regression: Java / Scala / Kotlin tabs, runnable snippets, and expected outputs from unit tests where available.

SubpackagePurpose
smile.feature.transform Scale, standardize, or row-normalize numeric columns
smile.feature.extraction PCA family, random projection, text / categorical encoders
smile.feature.imputation Fill missing values before training
smile.feature.selection Rank or search for informative features
smile.feature.importance SHAP / TreeSHAP explanations

Column-wise transformers return InvertibleColumnTransform (extends Transform) and chain with Transform.pipeline(...). Deep manifold methods (UMAP, t-SNE, LLE, …) live on the Manifold Learning page; here we keep PCA / KernelPCA / GHA / RandomProjection as feature extractors.

Feature Transformation

Package smile.feature.transform: five column-wise invertible scalers plus a stateless row-wise Normalizer. Fit on training data, then apply to train/test (and invert when you need the original scale).

Scaler

Min–max scaling maps each column to [0, 1] using training min/max. Out-of-range values are clamped, so invert is lossy outside the training range. Prefer when algorithms want bounded inputs and outliers are mild.

import smile.datasets.Iris
import smile.feature.transform.Scaler

var iris = new Iris()
var scaler = Scaler.fit(iris.data())
var scaled = scaler.apply(iris.data())
var restored = scaler.invert(scaled)
scaled.getDouble(0, 0)

first petal length scaled ∈ [0, 1]

WinsorScaler

Outlier-robust min–max: default 5th–95th percentile bounds (via IQAgent), then scale to [0, 1]. Use when extreme tails would crush the range of ordinary values.

Chain with Transform.pipeline(...) when stages are already fitted, or Transform.fit(data, trainer1, trainer2, …) when each stage must see the previous stage’s output. See also base/DATA_TRANSFORMS.md.

import smile.datasets.Iris
import smile.feature.transform.MaxAbsScaler

// Fit each stage on the previous stage's output:

pipe.apply(df)

Feature Extraction

Package smile.feature.extraction: linear and nonlinear projections plus encoders that turn text / categoricals into numeric vectors.

Principal Component Analysis

Orthogonal projection onto directions of maximum variance. PCA.fit uses the covariance matrix; PCA.cor uses correlations when scales differ. Keep top components by count or cumulative variance.

import smile.datasets.PenDigits
import smile.feature.extraction.PCA
import smile.plot.swing.ScatterPlot
import smile.plot.swing.ScreePlot

var pen = new PenDigits()
double[][] x = pen.x()
int[] y = pen.y()

var pca = PCA.fit(x)
double[] vp = pca.varianceProportion().toArray(new double[0])
new ScreePlot(vp).figure().show()              // scree plot below

double[][] x3 = pca.getProjection(3).apply(x)
ScatterPlot.of(x3, y, '.').figure().show()     // 3D projection below

(opens scree plot, then 3D PenDigits projection)

Missing Value Imputation

Real datasets often contain missing entries from nonresponse, dropout, sensor failure, or researcher error. Before imputing, ask why values are missing — the mechanism drives which methods are safe.

MCAR (missing completely at random): missingness is unrelated to any variable; complete-case analysis is unbiased but wasteful. MAR / covariate-dependent: missingness depends on observed variables, not on the missing values themselves — most modern imputers target this ignorable case. Non-ignorable (MNAR): missingness depends on the unobserved value (e.g. high incomes withheld); simple imputation can be badly biased and needs specialized modeling.

Imputation is not the only option: EM can estimate models with missingness directly, and some learners tolerate missing inputs when absence is structural rather than measurement noise. When you do impute, treat filled values as uncertain relative to truly observed ones.

Package smile.feature.imputation. DataFrame null and matrix NaN count as missing. Imputers implement Transform; check rows with SimpleImputer.hasMissing(tuple).

SimpleImputer

Column-wise constant fill — a fast baseline when missingness is roughly MCAR. fit(df) uses the median for numeric columns, the mode for boolean/nominal columns, and empty string for text. fit(df, lower, upper) imputes numerics with the mean of values between those percentiles (e.g. 0.0, 1.0 for the full mean). Or pass a custom Map of column → constant to the constructor.

import java.util.Map
import smile.datasets.Iris
import smile.feature.imputation.SimpleImputer

var df = new Iris().data()
var median = SimpleImputer.fit(df)                 // default: median
var mean = SimpleImputer.fit(df, 0.0, 1.0)         // mean in [0,1] percentiles
var custom = new SimpleImputer(Map.of("sepallength", 5.0))
median.apply(df)

KNNImputer

For a row with a missing attribute i, find k neighbors that have i observed and are closest on the other complete attributes (e.g. Euclidean), then fill with their (distance-weighted) average on i. Prefer when nearby rows share local structure. Constructor takes the reference frame + k (optional distance / columns); no separate training step beyond storing neighbors.

import smile.datasets.Iris
import smile.feature.imputation.KNNImputer

var df = new Iris().data()
var imputer = new KNNImputer(df, 5)  // Euclidean on all columns
imputer.apply(df)

KMedoidsImputer

k-medoids clustering (k-means with a real data point as the center). Missing entries in a row are copied from the nearest medoid. Fit with KMedoidsImputer.fit(df, distance, k) — useful for mixed-type data when a missing-tolerant distance is available.

import smile.datasets.Iris
import smile.feature.imputation.KMedoidsImputer
import smile.math.MathEx

var df = new Iris().data()
var imputer = KMedoidsImputer.fit(df,
    (x, y) -> MathEx.distanceWithMissingValues(x.toArray(), y.toArray()), 3)
imputer.apply(df)

SVDImputer

Low-rank matrix completion via SVD. Given A = U Σ VT, estimate missing entry (i, j) by regressing row i on the top k right singular vectors (excluding column j), then reconstructing from that linear combination. Because SVD needs a complete matrix, missing cells are first filled (e.g. column means); EM then iterates estimate → re-factorize until the change falls below a threshold.

Unlike the other imputers, SVDImputer.impute works on double[][] with NaN markers (not a DataFrame Transform). Best when numeric features are strongly correlated / approximately low-rank.

import smile.feature.imputation.SVDImputer
import smile.math.MathEx

MathEx.setSeed(19650218)
double[][] X = ... // may contain NaN
double[][] filled = SVDImputer.impute(X, 5, 100)

Feature Selection

Package smile.feature.selection: fast univariate filters plus GAFE as a wrapper search.

Hughes effect. With fixed sample size, adding irrelevant dimensions eventually hurts predictive accuracy (curse of dimensionality). Prefer ranking/selection or projection before distance-based models.

SignalNoiseRatio

Binary classification filter: |μ₁ − μ₂| / (σ₁ + σ₂) per feature (Golub-style). Higher is better.

import java.util.Comparator
import smile.datasets.BreastCancer
import smile.feature.selection.SignalNoiseRatio

var data = new BreastCancer().data()
var scores = SignalNoiseRatio.fit(data, "diagnosis")
java.util.Arrays.stream(scores)
    .sorted(Comparator.reverseOrder())
    .limit(5)
    .forEach(System.out::println)
